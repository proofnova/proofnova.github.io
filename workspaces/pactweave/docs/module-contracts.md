# PactWeave implementation contract

Frozen architecture: original request → intent analyzer → requirements contract → model-free context preprocessing → bounded execution/review/repair loop → evidence and final report. Wiki/RAG and the LLM gateway are optional branches inside planning/execution/review, never mandatory entry gates. One public skill: `pactweave`. English default, Korean/Japanese/Simplified Chinese editions.

## Public execution API

`await runWorkflow(spec, options)` in `src/pact-loop.mjs`.

`spec` contains `{request, project_id?, session_id?, task?, acceptance_criteria?, constraints?, assumptions?, required_inputs?, answers?, knowledge?}`. `task` is `{adapter, input}` or a bounded `jobs` DAG. A criterion is `{id, path, operator: "equals"|"exists"|"gte"|"lte"|"includes", expected, critical: true}`; it addresses the returned adapter envelope, e.g. `result.summary.accepted`. Missing adapter/input or ambiguous instructions produce structured questions and `BLOCKED`, never invented execution.

`options` contains `{store, registry, retriever?, gateway?, policy?, budgets?, signal?, repair?, now?, previous?}`. The registry supplies `list(), describe(id), execute(id,input,context)`. Runtime inputs cannot register executable functions or shell strings. `repair` is an explicitly trusted host callback. Browser uses memory storage; Node uses the file store. Both run the same pure analyzer/contract/loop and adapter implementations.

The result contains `{schema_version:1, task_id, project_id, session_id, original_request, original_request_digest, contract, plan, state, reason?, iterations, output, evidence, events, knowledge_queries, llm, metrics, capabilities, report}`. States are `ANALYZE, PLAN, EXECUTE, REVIEW, REPAIR, PASS, BLOCKED`; `BLOCKED` distinguishes prerequisites, permissions, unsupported functionality and budget exhaustion. Every final criterion has actual evidence; critical checks cannot be averaged away. `PASS` requires current output, intact request/contract digests and every criterion passing. No executor means no PASS.

## Main-owned pure modules

- `shared.mjs`: `PactError(message,code,details?)`, `assert(condition,message,code?)`, `canonical(value)`, async `digest(value)`, `clone(value)`, `safeId(value,label?)`, `getPath(value,path)`, `words(text)`, `redact(value)`.
- `request-intent-analyzer.mjs`: async `analyzeRequest(spec)` returns original request, interpreted intent, explicit/implicit constraints, task/domain/environment, missing inputs, uncertain assumptions, approval actions and conflicts. Rule-only interpretation is explicitly labeled.
- `requirements-contract.mjs`: async `createContract(spec,analysis)`, `validateContract(contract)`, async `applyAnswers(contract,answers)`; immutable original and digest, explicit field validation, critical criteria, question handling. Contract hash excludes the hash field itself.
- `context-preprocessor.mjs`: async `preprocessContext({contract,sessionRecords?,maxChars?})`; deduplicate stable records without deleting original/constraints/decisions; return preserved envelope plus bounded supplemental context and digests.
- `security-policy.mjs`: `createPolicy(options?)`, `authorize(action,policy,details?)` returns `{allowed,reason}`. Restricted network, paid disabled, automatic downloads disabled; explicit action grants required for processes/writes/push/credentials/deletions/external transfer. No credentials in public records.

## Planning findings resolved: mandatory implementation details

1. No vacuous PASS: an executable task requires at least one validated, nontrivial user outcome criterion in addition to engine-owned execution, digest, input-schema and adapter-output invariants. Missing criteria produce a stable typed question; an empty list never disables the built-in invariants. Every criterion is critical by default. Unsupported operators/paths/types are invalid, not silently skipped.
2. Contract identity binds original bytes, confirmed constraints, permissions, acceptance criteria and allowed adapter IDs. Mutable input/plan revisions have their own digest. A trusted repair may change adapter input or job planning data within that immutable contract, never criteria, original request, authority or scope. Every repair records before/after digests and the real failed checks. An explicit new requirement needs a new contract revision, invalidates prior evidence/cache and is never an automatic repair.
3. Job schema: `{id, adapter, input, depends_on:[], resources:[], side_effects:[]}`. Dependencies are job IDs; outputs are `{jobs:{[id]: adapterEnvelope}}`, so criteria address `jobs.id.result...`. Side-effect declarations are checked against adapter metadata and trusted host grants, not taken as authority from task JSON. Shared resource writes serialize. Dependent jobs do not execute after failure; event logs identify actual executed handlers/roles. Provider-backed AI roles are optional and must be labeled separately from deterministic role functions.
4. Answers are typed data, keyed by stable question IDs (`task.adapter`, `task.input`, `acceptance_criteria`, plus explicit required-input IDs). Answers fill only named unresolved data; ordinary strings cannot grant permissions or change confirmed constraints. Resume checks stored project/session/original/contract digests and counters against the authoritative store. A caller-provided report is an untrusted import, never proof of completion. PASS is recomputed from actual saved output/evidence. Attempts, model calls, elapsed time and repeated-error counters persist and never reset through resume. Explicit budget increases require host options and remain visible; prior spent counters stay.
5. Trusted policy is supplied only by the programmatic caller or explicit CLI allow flags, separate from task JSON, answers, cache and retrieved text. Effective action is the intersection of host grants and contract permitted actions; forbidden actions always win. Recheck immediately before effects and after asynchronous callbacks, including cache returns. Unknown network/process/credential operations remain disabled.
6. Current source manifests come from retriever/store content hashes, not model assertions. Exact response reuse validates project/session/model/context/requirements/permissions/current source versions and expiry. Similar responses remain provenance-tagged untrusted supplemental context. In-flight dedup uses that full identity and rechecks cancellation/revocation before return or cache admission. Separate exact-hit avoided calls, coalesced calls and context-only matches. Local cache is physically separate from the long-term four-area store.
7. Store uses private ignored state, strict IDs and project/session scopes, rejects symlinks/reparse paths, and serializes writes with an exclusive lock or reports conflict. Records have schema/digests and atomic replacement; corrupt records are quarantined/fail-closed, not converted into empty success. Delete erases live record/index/history/cache in its documented scope and leaves a non-sensitive tombstone so recovery cannot resurrect it. User-created external backups are explicitly outside erase scope. Default exports redact sensitive keys; including raw sensitive sessions is an explicit opt-in. `prune({before,area?,session_id?})` and `reindex()` provide retention/index operations. Unknown schema versions fail explicitly.
8. Host process adapter is optional, CLI-only, explicit command+argv, scope/cwd verified, minimal environment, bounded output/timeout/cancellation, shell:false. Never derive commands from prose. No arbitrary shell interpreters or inline scripts. Running a user-approved project test file is executing trusted local code, not an OS sandbox; require an explicit host execution grant. Runtime detection reports installed/missing for Node, Python, Java, Go, Rust, Shell, PowerShell, SQL CLI, Docker and Kubernetes; detecting a runtime does not imply full domain automation. Unsupported or missing-runtime jobs return concrete BLOCKED remedies.
9. CLI exit codes: 0 successful command/PASS, 1 validation or execution failure, 2 missing data/unsupported/runtime prerequisites, 3 approval required, 4 budget exhaustion/cancelled. `--json` writes one JSON document to stdout; diagnostics go to stderr. Commands accept a JSON file or `-` stdin; quoted text is accepted by analyze. No mandatory runtime packages. Node 22+ is required; only Windows is locally executed here, Linux/macOS support is verified by CI configuration and portable logic, not claimed as locally run.
10. Browser has actual pure execution for the thirty shipped adapters, intent/contracts/PactLoop/WeaveMesh, in-memory cache and local BM25 search. Browser disk recovery, process execution and host model clients are explicitly Local CLI Required. Node uses real persistent storage and optional explicitly configured provider callbacks; built-in model/network calls are disabled. Model-less unknown semantic tasks are BLOCKED with clear next inputs, not claimed completed.
11. Distinctiveness is a falsifiable practical hypothesis: one installed entry preserves an immutable acceptance contract through local execution, stale-source cache invalidation, negative review, and persisted resumption while skipping unnecessary retrieval/models. Synthetic paired fixtures exercise full/no-cache/no-retrieval configurations with identical inputs/criteria; raw outputs, failures, calls and timings are saved. A plain-model arm is executed only if an actual configured local model is available; otherwise NOT_RUN, never replaced with a mock labeled as a model. Standard algorithms are not claimed invented, and no 95% or Stars-selection claim is made without appropriate real evidence.
