## 빠른 시작

Node.js 22 이상이 필요합니다. 추가 패키지 설치는 필요 없습니다.

```sh
git clone https://github.com/proofnova/csv-harmonizer.git
cd csv-harmonizer
npm test
node cli.mjs example.json
```

## 어떤 일을 하나요

CSV 열 별칭·자료형·중복·충돌을 정리하고 격리 행과 출처를 반환한다.

### 필수 입력 항목

`sources` · `schema` · `keys`

필드 이름은 공개 인터페이스의 일부이므로 언어가 바뀌어도 유지됩니다. 완전한 입력은 [예제 파일](example.json), 정상·경계 사례는 [검증 사례](cases.json)에서 확인하세요.

### 실행 예제의 결과

```json
{
  "accepted": 2,
  "rejected": 1,
  "duplicates": 1,
  "conflicts": 0
}
```

아래 값은 포함된 합성 예제를 실행한 결과입니다. 모델 성능이나 실제 사용자 수를 나타내는 수치가 아닙니다.

## 모델과 연결하기

실행 모듈의 `execute` 함수를 명시적인 도구로 등록하고, 선택한 도구와 입력을 검사한 뒤 반환된 결과와 입력 해시를 보관하세요. 사용자나 연동 코드가 리소스를 선택하며, 실제 계산은 정해진 코드가 수행합니다. 모델의 자율 추론을 입증하는 방식은 아닙니다.

[AI 스킬](SKILL.md)에서 입력 검사·결과 해석·복구 절차를 안내합니다. 브라우저에서도 같은 계산을 실행 시간에 제한이 있는 작업자로 처리하며 입력을 전송하지 않습니다.

## 검증과 복구

포함된 테스트는 합성 업무 사례 두 개, 서버용·브라우저용 계산의 일치, 원본 입력 보존, 필수 입력 누락 거부를 확인합니다. 변경 후에는 `npm test`를 실행하세요.

결과를 사용하기 전에 보류·거부·실행 불가능 항목을 확인하세요. 입력이나 명시한 제약의 원인을 수정한 후 다시 실행하고, 미해결 항목을 성공으로 처리하지 마세요. 정확한 규칙과 개별 한계는 작업 계약과 스킬에서 확인하세요.

## 범위와 한계

기반 알고리즘과 업무 결과에는 기존 구현이 있습니다. 실용적 차별성은 검증할 가설이며, 기존 도구의 설정만으로 더 잘 해결할 수도 있습니다. 합성 회귀 검사는 모델의 일반적인 전문성이나 실제 외부 효과를 입증하지 않습니다. 기록된 모델 비교는 합성 업무 여섯 개에 한정되며 리소스 서른 개 전체를 검증한 결과가 아닙니다. 외부 사용자나 공식 깃허브 스타 회원 지위는 확인되지 않았습니다.

## 기여하기

재현 가능한 합성 또는 비식별 입력, 예상 결과, 사용한 실행 환경 버전을 알려주세요. 회귀 사례를 추가하고 테스트를 실행하세요. 공개 예제에 인증 정보나 실제 비공개 기록을 넣지 마세요.
