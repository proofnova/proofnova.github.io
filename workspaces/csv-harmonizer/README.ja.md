[作業画面を開く](https://proofnova.github.io/csv-harmonizer/) · [すべてのリソース](https://proofnova.github.io/) · [作業契約](resource.json) · [既存手段と調査](RESEARCH.md)

## クイックスタート

Node.js 22以上が必要です。追加パッケージのインストールは不要です。

```sh
git clone https://github.com/proofnova/csv-harmonizer.git
cd csv-harmonizer
npm test
node cli.mjs example.json
```

## できること

CSVの列名・型・重複を整理し、除外行と出典を保持します。

### 必須入力

`sources` · `schema` · `keys`

フィールド名は公開インターフェースの一部であり、表示言語が変わっても維持されます。完全な入力は[入力例](example.json)、正常・境界例は[検証ケース](cases.json)をご覧ください。

### 実行例の結果

```json
{
  "accepted": 2,
  "rejected": 1,
  "duplicates": 1,
  "conflicts": 0
}
```

値は同梱の合成例を実行した結果です。モデル性能や実際の利用者数を示す値ではありません。

## モデルと接続する

実行モジュールの `execute` 関数を明示的なツールとして登録し、選択したツールと入力を検証して、返されたJSONと入力ハッシュを保存します。リソースを選ぶのは利用者または連携コードであり、計算は決められたコードが行います。モデルの自律的推論を実証する仕組みではありません。

[AIスキル](SKILL.md)は入力確認・結果解釈・復旧を案内します。ブラウザーでも同じ計算を時間制限付きのワーカーで実行し、入力は送信しません。

## 検証と復旧

同梱テストは合成業務例二つ、Nodeとブラウザーの計算の一致、入力の非変更、必須入力不足の拒否を確認します。変更後は `npm test` を実行してください。

結果を利用する前に保留・拒否・実行不能の項目を確認してください。入力や明示した制約の原因を修正して再実行し、未解決の項目を成功と扱わないでください。詳細な規則と個別の制限は作業契約とスキルにあります。

## 範囲と限界

基盤となるアルゴリズムと業務結果には既存の実装があります。実用的な違いは検証対象の仮説であり、既存ツールの設定でより適切に解決できる場合もあります。合成回帰テストは一般的なモデルの専門性や外部での効果を実証しません。記録済みのモデル比較は合成業務六つに限定され、三十リソース全体の検証ではありません。外部利用者や公式GitHub Stars会員資格は未確認です。
